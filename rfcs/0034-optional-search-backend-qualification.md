# RFC-0034: 可选搜索后端的资格验证

- **Status**: draft
- **Created**: 2026-09-09
- **Tracking**: 用户本日授权重新评估适当位置的 ripgrep / fd；PR #1426 的接口删除仍待审
- **Affected source paths**: `source_lines.py`、`mcp/tools/{search_facade,trace_impact_tool}.py`、`cli/`、既有搜索测试与基准
- **Supersedes**: 提议替换 RFC-0033 对可选加速的排除，并把其“不启动外部搜索进程”“无 rg/fd 安装步骤”验收项限定到默认核心路径及核心安装；保留原生独立运行、安全边界及公开接口迁移约束

## Summary

核心安装不强制依赖 rg/fd；允许依据正确性和实际任务收益选择可选后端。优先评估 rg 的精确文本候选检索，暂不接入 fd 的索引文件发现。此次先建立资格验证与准入条件，不把检测到可执行文件等同于可以自动切换，不改默认后端。

本提议接受后，RFC-0033 的对应验收解释为：默认内部发现/trace 不启动外部搜索进程，核心安装不安装或要求 rg/fd；显式可选路径及隔离资格任务可启动或安装已锁定的程序。可选后端并不免除其余预算、安全和迁移验收。接受前仍沿用原约束。

## Motivation

用户明确允许在有用的位置重新引入 rg/fd。去掉强制依赖与使用成熟的可选实现可以并存。主要目标是缩短从问题到可核验源码的路径，而不是增加门面、恢复全部旧参数转发或追求一个孤立扫描速度。

2026-09-09 在 macOS 本机四文件临时目录进行差异探测（TSA `378db30e`，rg 15.1.0，fd 10.4.2），使用 `rg --no-config --json -F needle ROOT`、`fd --type f --absolute-path . ROOT` 与 TSA `scan_symbol_lines` / `workspace_files`：

| 输入 | TSA | 外部程序 |
|---|---|---|
| `normal.py = b'zero\nneedle\n'` | 命中第 2 行 | rg 命中第 2 行，输出保留末尾换行 |
| `cr.py = b'zero\rneedle\r'` | 命中第 2 行 | rg 命中第 1 行，整段 CR 文本作为一行 |
| `binary.py = b'needle\n\x00tail'` | 不返回文本命中 | 此次 rg 同样不返回文本命中 |
| `.rgignore` 排除 `ignored.py` | 文件发现排除它 | fd 此次仍返回它 |

这是输入分区的局部见证，不是跨平台等价性或速度声明。此前本机吞吐对比也不是准入依据；外部后端只有在统一语义、包含边界检查和源码核验成本之后仍有收益才值得集成。

## Detailed design

### 能力分工

1. 已知符号、调用关系、影响范围：继续使用 AST / 图索引。
2. 不知道符号名的问题：先评测现有词法和 embedding 检索的入口质量，再决定如何组合。RFC-0016 曾因实测收益不足而被拒绝，不能把另一项目的成功叙述当作重启依据。
3. 精确字符串、错误消息、配置键、未索引文档：rg 是优先候选；它提供文本候选，不证明 AST 调用关系或索引新鲜度。
4. 文件名发现：先复用已有原生发现和宿主工具。fd 只有在独立证明忽略规则、隐藏路径与完整集合一致且整体更有效后才进入实现阶段。

### 后端准入

- 不改变项目根校验、符号链接/普通文件限制、读取权限、字节预算、超时、进程回收或源码版本证据。
- 对现有 trace 的替换必须保持精确文件、行号、文本、计数及失败语义。不能只对命中行重新验证：遗漏的候选同样会制造假阴性。
- rg 的换行、二进制检测、Unicode 大小写和单词边界与 Python 实现分别测量。不能通过 `strip()` 等有损归一化让差异消失。
- 禁止让外部递归遍历直接成为认证索引的文件集合权威。只有通过共同作用域资格验证的输入才可比较完整召回。
- 原生读取所保证的边界必须在外部读取之前成立。仅检查返回路径不足以证明外部进程没有读越界文件。若直接路径扫描无法通过文件替换/链接竞态测试，评估受控字节输入或隔离快照，并将准备成本计入测量；否则不接入该安全敏感路径。
- 外部程序采用参数数组启动，禁用宿主搜索配置，不执行 shell 拼接、任意参数转发、预处理器或自动安装。
- 区分正常零匹配、执行失败、输出损坏、超时与展示截断。发生错误不能返回成功空集；不能用静默回退掩盖失败或累计突破预算。
- 可执行程序缺失时核心功能仍可用。未来显式指定某外部后端而该后端不可用时，应明确报错；自动选择策略需要单独验收。

### 分阶段交付

**阶段 A：资格验证。** 复用既有测试模块建立原生与外部候选的差异矩阵；基准在隔离环境运行，不引入生产后端选择。记录工具版本、仓库 SHA、操作系统、输入大小、完整结果差异、失败分类、进程和核验成本。阶段 A 的交付不声称已加速。

**阶段 B：受限实现。** 只有阶段 A 找到正确且有实际收益的场景后，选择一个场景、一条已有 CLI/MCP 路径实现；明确参数、默认值、响应元数据、缺失程序与失败行为，再提交本 RFC 的实现细化。仍默认原生；不因为 PATH 上恰好有 rg 就改变语义。

**阶段 C：自动策略。** 只有配对任务评测证明有收益，才讨论自动路由。索引热查、冷建索引、实时扫描和完整 agent 任务分别报告，禁止相互替代。

## Three-Surface impact (CLI ↔ MCP parity)

阶段 A 不新增任何生产 Python API、CLI flag、MCP action 或配置变量。
阶段 B 必须在实现前明确现有路径的 Python 参数、CLI 选项及 MCP 同名含义，并在同一 PR 完成真实 CLI/MCP 行为测试和 codemap 同步。JSON 协议继续保持。

PR #1426 的公开接口删除与可选后端是两个决定。本 RFC 不自动批准全部删除或恢复全部旧接口；尤其 sitemap 是索引结构视图，不能代替未索引文本/任意实时文件发现。删除候选需按任务覆盖重新核对迁移路径。

## Drawbacks and alternatives

双后端增加平台矩阵、故障路径和长期维护成本；共享作用域发现与安全核验可能抵消扫描收益。因此允许结论是某个场景不接入 rg，或 fd 没有必要。宿主直接调用 rg/fd 是有效替代；不会为了工具存在而增加 TSA 包装层。

## Prior art

- [ripgrep guide](https://github.com/BurntSushi/ripgrep/blob/master/GUIDE.md)：精确/正则搜索、过滤与二进制处理必须按实际行为比较。
- [fd](https://github.com/sharkdp/fd)：快速文件发现；默认忽略语义不能假定与 TSA 相同。
- [zvec-grep 固定版本检索管线](https://github.com/zvec-ai/zvec-grep/blob/6fa85a8e28c0b5a0f651c27f09f0247627c5d5c3/src/engine/pipeline/search/index.ts)：借鉴多路候选、证据组织和诊断；无需复制其依赖组合。
- [zvec-grep 配对评测](https://github.com/zvec-ai/zvec-grep/blob/6fa85a8e28c0b5a0f651c27f09f0247627c5d5c3/benchmarks/README.md)：固定任务、模型与环境，索引准备单独报告，参考答案与历史产物不进入检索工作区。

## Test plan (RED-first)

先写会击穿天真后端替换的用例：CR/LF/CRLF、Unicode 分词/边界、文件末尾 NUL、嵌套忽略及反忽略、仓库内外根、隐藏文件、重叠根、链接和文件替换、读取拒绝、单文件/总量/命中预算、超时、异常退出、输出损坏、后端缺失。测试精确集合和失败分类，不能只比较数量。

真实程序资格矩阵在运行前提交版本锁：rg 15.1.0、fd 10.4.2，各 OS/架构的下载地址和 SHA-256 必填；缺少锁值、下载校验失败或 `--version` 不符均在预检失败。比较单元使用相同工具版本；新增版本必须成为显式矩阵维度，不能用包管理器的 latest 替换。缺少程序时资格任务失败，不跳过。

核心独立性另设隔离任务或子进程：不调用安装 rg/fd 的 setup-system；构造受控 PATH，运行前分别证明 `which('rg')`、`which('fd')` 为空且按名称启动会失败，再运行真实核心 CLI/MCP 查询并检查返回内容。仅省略安装步骤不足以证明工具缺失。普通核心测试不新建 `requires_rg` 跳过网。

### 预注册的配对任务协议

以下数字是拟定的准入政策，不是已经实现的性能声明。阶段 A 的执行器必须先用合成结果验证判定器会拒绝质量退步、失败丢弃及未达到收益门槛的结果，才允许运行真实矩阵。

- **冻结任务**：上述五类各 4 个保留任务，共 20 个；在运行前提交任务 ID、仓库 SHA、环境/模型版本、提示、工具参数、每任务预算及评分规则的清单和哈希。每任务运行 10 个配对重复，不得看结果后换任务、选最佳 seed 或减少重复数。
- **控制组**：原生 TSA 与候选 TSA 使用相同 agent 工具白名单，两组都禁止 agent 直接调用宿主 rg/fd；仅受控候选适配器有执行权限。执行器检查进程轨迹，绕过白名单的样本记失败，不能仅靠提示词禁止。宿主直接搜索作为单独第三组时必须独立预注册，不能混入原生组。
- **防泄漏**：每组使用仅含固定被测仓库内容的工作区；参考答案、源码位置标注、评分器、历史轨迹与报告位于 agent 不可访问的外部目录。预检枚举允许的搜索根与可读挂载，发现这些评测产物可达就拒绝运行；评分器看不到组名和工具轨迹。
- **状态隔离**：每次重复、每个组分别恢复固定源码和编辑前 fixture，使用独立索引目录及新 agent 会话。冷/热条件分别执行并记录，不能继承另一组的编辑或索引；每任务 5 次 A→B、5 次 B→A，顺序在预注册清单固定。记录无法清空 OS 页面缓存的限制，冷/热分层报告，不把它包装成磁盘冷启动。
- **正确性底线**：确定性差异矩阵的文件/行号/文本/失败分类必须全部一致。任务按预先隐藏的必要事实及源码证据逐项判定；候选必须通过原生通过的每一个配对任务，且每类总成功数不能下降。任何越界、错误新鲜度认证或损坏输出冒充成功都直接拒绝准入。
- **失败处理**：不删除超时、异常和错误答案。它们均记任务失败，耗时按该任务预注册的总预算上限计入，两组同规则；环境预检失败不进入测量，而是整组无效，修复后重跑完整配对。
- **实际收益**：阶段 B 的目标任务类别在矩阵运行前固定。该类别配对总耗时比值（候选/原生）的中位数须不高于 0.90；其余每类中位数不高于 1.05，所有任务合并的 p95 总耗时不高于原生的 1.10 倍（p95 使用 nearest-rank）。总耗时包含进程启动、文件准备、索引、边界检查与源码核验；冷、热两层分别满足，不允许以单项扫描耗时替代。工具调用数和输入 tokens 同步报告，不在事后替代未通过的主要耗时指标。
- **判定**：正确性和收益条件全部通过才准入；任一条件失败为不接入，样本不完整为证据不足。改变政策须另行审查并重新冻结/运行，旧数据只作探索结果。尚未运行的协议不产生宣传倍率，也不扩大既有 E0–E3 证据授权。

- [ ] 阶段 B 的参数、错误和三表面契约细化并审查

## Deferred

新 embedding 模型/数据库、默认自动选择后端、全套 rg/fd 参数兼容、重新引入安装强依赖与发布动作均不在本次资格验证内。
